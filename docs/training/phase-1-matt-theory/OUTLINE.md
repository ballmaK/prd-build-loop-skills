# 一期大纲 · Matt 技能与 AI 落地心智模型

## 1. 我们要回答的问题

不是「哪个 AI 最好用」，而是：

1. AI 助手为什么经常交不出靠谱结果？  
2. 有哪些能反复使用的纪律，可以稳住质量？  
3. 这些纪律如何拼成一条研发落地链路？

## 2. 核心主张

Matt Pocock 这套技能 = **能组合的工程小技能**，控制权留在人手里。  
它想避开的是：一把梭的「全自动大流程」——出了问题难调试、也难改。

原则：**小、能改、能组合、不绑死某一个 AI 工具。**

## 3. 四类翻车（理论主干）

### 3.1 做的不是我想要的

- 原因：人自己也可能没想清；AI 就猜着做。  
- 解药：拷问对齐——一次一问、给推荐答案、决策归人、事实查仓库。  
- 常见入口：「拷问我」「拷问并写文档」。

### 3.2 说话又长又飘

- 原因：没有项目共同语言，AI 每次用很长一段解释一个词。  
- 解药：项目词表 + 架构决策记录 + 领域建模。  
- 收益：命名一致、好找代码、少浪费无效推理。

### 3.3 代码跑不通

- 原因：没有反馈环，AI 在盲飞。  
- 解药：类型检查、能看见页面、自动测试；核心是测试驱动（先红后绿再重构）。  
- 辅药：有纪律的排错流程。

### 3.4 系统糊成一锅粥

- 原因：写得越快，结构烂得越快。  
- 解药：关心模块设计；写规格前先问清落在哪条边界；定期做架构体检。

## 4. 两类技能（组织方式）

| 类型 | 谁触发 | 作用 | 例子 |
| ---- | ------ | ---- | ---- |
| 人主动触发 | 你 | 编排入口 | 拷问我、写成规格、按票实现 |
| 可被自动调用 | 你或 AI | 可复用纪律 | 拷问原语、测试驱动、领域建模 |

规则：入口可以调用纪律；入口和入口之间不互相套用。

## 5. 一条完整路径（落地简图）

```text
每个仓库先做一次初始化配置
  → 拷问并对齐文档（目标和术语）
  → 综合成规格（只总结，不再追问）
  → 拆成可领取的竖切任务
  → 小步实现 + 测试先行
  → 评审验收；会话太长就正式移交后续
```

重点纠偏：

- 「写成规格」这一步**不再拷问**；拷问要更早完成。  
- 特别大的需求，先探路，再拆票。

## 6. 常用能力速览（分享够用即可）

**对齐与领域：** 拷问我 / 拷问原语 / 拷问并写文档 / 领域建模  
**规格与拆工：** 写成规格 / 拆成工单 / 工单分流 / 探路地图  
**实现与质量：** 测试驱动 / 按票实现 / 代码评审 / 可扔原型 / 排错 / 调研  
**架构：** 深模块设计 / 架构体检  
**协作：** 会话移交 / 该用哪条技能 / 仓库初始化

## 7. 和我们仓库的分工（预告后续）

```text
Matt 这套          = 工程地基（怎么对齐、怎么测、怎么续跑）
我们的编排仓库      = 交付操作系统（需求生成/逆向/签核/循环实现）
```

一期只要求大家认路；二期装技能；三期用 PulseNotes 把新品路径跑通。

## 8. 带走三句话

1. **先对齐，再动手。**  
2. **反馈环是速度上限。**  
3. **小技能组合，大于大框架接管。**
