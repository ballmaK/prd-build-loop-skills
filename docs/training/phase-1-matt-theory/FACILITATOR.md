# 一期分享 · 教练 / 分享人脚本

## 开场（约 2 分钟）

> 今天不聊某个软件怎么点按钮，也不写代码。  
> 我们一起把 **Matt Pocock 这套技能** 当成一面镜子：看清 AI 写代码为什么容易翻车，落地时该先稳住哪些纪律。  
> 后面几期再动手；这一期先让脑子里有一张地图。

投影打开：`docs/briefings/matt-theory-share/index.html`

---

## 时间安排（约 45 分钟讲解 + 10 分钟答疑）

| 时间 | 板块 | 请强调的一句话 |
| ---- | ---- | -------------- |
| 0–5 分 | 为什么需要流程 | 快，不等于能交出去 |
| 5–15 分 | 四类翻车 | 错位最致命 |
| 15–22 分 | 两类技能 | 入口负责编排，纪律负责收得住 |
| 22–32 分 | 完整路径 | 先对齐，再写规格，再拆任务，再小步做 |
| 32–40 分 | 和我们怎么接 | Matt 是地基，编排是交付操作系统 |
| 40–45 分 | 带走三句话 + 预告 | 先对齐，再动手 |
| 45–55 分 | 答疑 | 先聊思路，装机细节放到二期 |

## 互动建议（至少做两件）

1. **举手投票**：四类翻车里，你上周最像哪一类？  
2. **口头对比**：同一需求「让它自由发挥」和「先对齐再写」差在哪。不必真开 AI，把后果说清楚即可。  
3. **速记**：请每人在笔记里写一句「我回去会先试的一个做法」。
