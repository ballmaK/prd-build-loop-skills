# 一期分享 · 教练 / 分享人脚本

## 定位

**场景分享 + 讨论**（约 50～60 分钟）。  
干货来自三个开工场景，不靠背技能清单。装机细节仍放二期。

投影：`docs/briefings/matt-theory-share/index.html`

---

## 开场（约 3 分钟）

> 今天不讲「技能有哪些」，讲「你明天怎么开工」。  
> 三种常见状态：PRD 还不明确的新品；已经写了一截要续接；几乎没文档的老系统。  
> 每种先说坑，再说路径，再留讨论。

请听众先在心里选一个：**我最近最像哪一种？**

---

## 时间安排

| 时间 | 板块 | 注意 |
| ---- | ---- | ---- |
| 0–5 分 | 开场 + 认场景 | 举手分三类 |
| 5–20 分 | 场景 1 新品 · PRD 不清 | 强调：对齐 → 挑战门 → 才实现 |
| 20–35 分 | 场景 2 在建续接 | 强调：别当白板；先钉已有行为 |
| 35–50 分 | 场景 3 老旧改造 | 强调：As-Is ≠ backlog |
| 50–55 分 | 三场景对照 + 地基 | 一张表收束 |
| 55–70 分 | 分组讨论 / 答疑 | 每组只答一个讨论题 |

若总时长只有 45 分钟：场景各压到 8 分钟，讨论改成全场选 2 题快答。

---

## 每个场景的讲法（固定四拍）

1. **手头有什么**（30 秒）  
2. **常见错误**（1～2 分钟，举你们组内真实例子更好）  
3. **推荐路径与产物**（3～4 分钟，指着幻灯片步骤）  
4. **丢出讨论题**（先记着，后半场再展开）

---

## 讨论题（现场选用）

**场景 1**

- 你最近一个新品需求，卡在目标 / 边界 / 验收哪一层？  
- 多做一件事再写码，选「拷问」还是「先写测试」？

**场景 2**

- 「文档有、代码无」最近一次怎么发现的？  
- 更怕改坏旧功能，还是新功能接不上？

**场景 3**

- 没文档时你更信口述、日志还是代码？怎么交叉验证？  
- 「先表征再改造」慢在哪、省在哪？

## 这一期先别讲深

- 各工具安装目录与命令细节  
- PulseNotes 逐步跟练（三期）  
- 迁移绞杀策略的完整工程方案

---

## 收尾口播

> 先认场景，再选路径。  
> 新品：写清再挑战再写码。  
> 续接：先摸清已有，再补下一批 To-Be。  
> 老改：先忠实 As-Is，再谈目标态——现状描述不是待办清单。

预告：二期装技能与触发；三期用 PulseNotes 把场景 1 跑通；四期加场景 3 进阶。
