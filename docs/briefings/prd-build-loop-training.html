02 / 换个定义

Skills 不是提示词收藏夹，是可搬运的工作流

把「怎么提问、做到哪停、产物落哪里」写成技能。换工具只换触发方式，不换做事顺序。

  • 01
    看产物，不看哪家 UI成功与否看 docs/prd、签核、active-plan
  • 02
    触发可用斜杠或自然语言有的工具是 /技能名，有的是一句话说清
  • 03
    人和 Agent 分工固定你做决策，它做探索、综合、小步实现

一句话记住

先对齐，再动手。一次只推进一步。

03 / 工具适配

Cursor、OpenCode、其他 Agent，同一条流程

你要做的事 统一说法 成功信号（跟工具无关）
安装本套技能 npx skills add … --agent <你的工具> 技能列表里出现 prd-author / prd-reverse / prd-grill / prd-build-loop
触发技能 /prd-author 或「按 prd-author 帮我…」 Agent 进入该技能的阶段规则，而不是自由发挥长文
判断是否做对了 打开产物路径核对 docs/prd/、*-signoff.md、active-plan.md 出现且内容合理

没有 slash 也没关系：用自然语言点名技能。关键是产物路径，不要跟某个 IDE 按钮死磕。

06 / 绿场跟练

新想法：抄这三段触发语

第 1 步

生成 PRD

触发：prd-author 说法：按 prd-author，从我的想法生成模块化 PRD。一次只问一个问题。

产物：docs/prd/00-macro-shared.md + modules/*

第 2 步

成品挑战

触发：prd-grill 说法：按 prd-grill 挑战现有 PRD，通过后写签核。

产物：docs/prd/grill-signoff.md 且 status: approved

第 3 步

循环实现

触发：prd-build-loop 说法：按 prd-build-loop 开始实现；每次只做一个任务。

产物：active-plan 勾选推进 + 小步提交

Training · Skills Workflow

07 / 棕地跟练

老项目：先还原，再谈改造

第 1 步

逆向 As-Is

触发：prd-reverse 说法：按 prd-reverse 从当前代码生成 As-Is PRD。猜的请标 hypothesis。

产物：docs/prd/as-is/ + reverse-signoff

第 2 步

锁行为再改

在将要动的边界补表征测试，锁住今天的外部行为。然后再写 To-Be / 迁移计划，最后才进 build-loop。

口诀：先拍照片，再做手术。

08 / 三铁律

培训现场最该记住的三件事

Ask

一次只问一个问题

挑战阶段连发五问，你会答到糊。决策归你，事实归仓库。

Build

一次只做一个任务

一个 checkbox = 一次迭代。想顺便重构半个系统，就会失控。

Gate

不过门不写代码

没有 approved 签核，就不启动实现环。急也要急在对齐上。

09 / 常见翻车

这三坑，同事们最容易踩

忘了签核就实现

现象：直接 build-loop。修法：先看 grill/reverse signoff 是否 approved。

把 As-Is 当 backlog

现象：逆向文档丢给实现。修法：As-Is 只证明现状，改造要有 To-Be/迁移任务。

一会话塞太多任务

现象：上下文爆炸、越改越飘。修法：满 3–5 个任务就 handoff，新开会话续跑。

10 / 回去怎么练

今晚只用真实需求跑一段

  • 选一个真实、小的需求（别选“重构整个系统”）
  • 先判定绿场还是棕地
  • 装好技能后，只跑到「签核通过」也算完成
  • 若进入实现：最多完成 1 个竖切任务就停下复盘
  • 记下：卡在哪、产物有没有、哪句触发语最有效

自检三问

1. 我能否向同事讲清这次改动的目标与非目标？

2. 仓库里能否指出对应产物文件？

3. 若换一个 AI 工具，我是否仍知道下一步触发哪项技能？
