iron-rules

培训现场最该记住的三件事

一次一问

挑战阶段连发五问会答糊。决策归你，事实归仓库。

ask

一次一任务

一个 checkbox = 一次迭代。想顺便重构半个系统就会失控。

build

不过门不写

没有 approved 签核，就不启动实现环。急也要急在对齐上。

gate
ask · atomic · gate
让大家合唱或复述三铁律。这是培训记忆锚点。

pitfalls

这三坑，同事们最容易踩

忘了签核就实现

现象：直接 build-loop。
修法：先看 signoff 是否 approved。

把 As-Is 当 backlog

现象：逆向文档丢给实现。
修法：改造要有 To-Be/迁移任务。

一会话塞太多任务

现象：上下文爆炸。
修法：满 3–5 个任务就 handoff 续跑。

debug the process
用反例巩固铁律。问：上周有没有人中招？

homework

今晚只用真实需求跑一段

1选一个真实、小的需求别重构全世界
2判定绿场还是棕地30 秒
3跑到签核通过也算完成对齐优先
